# เช็กลิสต์ ASO — Apple App Store และ Google Play

เช็กลิสต์ App Store Optimization สำหรับผู้สร้างแอปและเอเจนต์ AI อัปเดตเมื่อ **2026-10-01**

## หากคุณเป็นเอเจนต์ AI อ่านส่วนนี้ก่อน

1. **โหมดเริ่มต้นคือการตรวจ (audit)** อ่านหน้าสโตร์ ทำเครื่องหมายทุกรายการด้านล่าง แล้วรายงานผล
   แก้ไฟล์เฉพาะเมื่อผู้ใช้ขอให้แก้ **ห้ามอัปโหลดขึ้น App Store Connect / Play Console หรือส่งแอปเข้ารับการตรวจสอบ**
   เว้นแต่ผู้ใช้ขอไว้ในบทสนทนานี้
2. **หาหน้าสโตร์ให้เจอ** fastlane: `fastlane/metadata/ios/<locale>/*.txt` (หรือ
   `fastlane/metadata/<locale>/`) และ `fastlane/metadata/android/<locale>/*.txt` ถ้าไม่มี
   ให้ขอผู้ใช้วางชื่อแอป / ชื่อรอง / คำสำคัญ / คำอธิบาย ของแต่ละภาษา หรือชื่อ / คำอธิบายแบบย่อ /
   คำอธิบายแบบเต็มของ Play
3. **นับด้วยโค้ด ห้ามกะด้วยตา** รายการที่มีป้าย **(auto)** ตรวจได้ด้วยสคริปต์ฟรีนี้:
   ```bash
   curl -sSLO https://raw.githubusercontent.com/shipflutter/skills/develop/skills/aso/scripts/aso_check.py
   python3 aso_check.py --root .            # markdown report; exit 1 on errors
   curl -sSLO https://raw.githubusercontent.com/shipflutter/skills/develop/skills/aso/scripts/keyword_suggest.py
   python3 keyword_suggest.py "habit tracker" --az --country us --competition
   ```
   (Python 3.10+ ใช้เฉพาะไลบรารีมาตรฐาน ไม่ต้องใช้ API key)
4. **ทำเครื่องหมายทุกรายการ** `✅ pass` (ผ่าน) / `⚠️ improve` (ควรปรับ) / `❌ fail` (ไม่ผ่าน) / `N/A` (ไม่เกี่ยวข้อง) พร้อมหลักฐาน (ไฟล์ จำนวน ข้อความที่ยกมา)
   ทุก ⚠️/❌ ต้องมีวิธีแก้ที่เป็นรูปธรรมและไม่เกินขีดจำกัด ใช้แม่แบบรายงานท้ายไฟล์นี้
5. **อย่าแต่งข้อมูลขึ้นเอง** ห้ามใส่ปริมาณการค้นหา อันดับ หรือคะแนนที่คุณไม่ได้วัดเอง
   ให้เขียนว่า "ยังไม่ได้วัด" แทน ข้อมูลที่ระบุว่า UNCONFIRMED ด้านล่างเป็นข้อสังเกตจากผู้ให้บริการเครื่องมือ ไม่ใช่กฎของสโตร์

## ขีดจำกัดโดยสรุป

| สโตร์ | ช่อง | ขีดจำกัด | ทำดัชนีสำหรับการค้นหา |
|---|---|---|---|
| App Store | ชื่อแอป | 30 | ✅ มีน้ำหนักมากที่สุด |
| App Store | ชื่อรอง | 30 | ✅ |
| App Store | ช่องคำสำคัญ (ซ่อนอยู่) | 100 | ✅ |
| App Store | ข้อความโปรโมต | 170 | ❌ (แก้ได้โดยไม่ต้องผ่านการตรวจ) |
| App Store | คำอธิบาย | 4000 | ❌ สำหรับการค้นหาใน App Store |
| App Store | มีอะไรใหม่ (What's New) | 4000 | ❌ |
| App Store | อีเวนต์ในแอป (in-app events): ชื่อ / คำอธิบายสั้น / คำอธิบายยาว | 30 / 50 / 120 | ✅ ชื่ออีเวนต์ |
| App Store | ชื่อที่แสดง / คำอธิบายของ IAP | 30 / 45 | ✅ IAP ที่โปรโมต |
| Google Play | ชื่อ | 30 | ✅ มีน้ำหนักมากที่สุด |
| Google Play | คำอธิบายแบบย่อ | 80 | ✅ |
| Google Play | คำอธิบายแบบเต็ม | 4000 | ✅ (ไม่มีช่องคำสำคัญแบบซ่อน) |
| Google Play | มีอะไรใหม่ (What's new) | 500 | ❌ |

เอกสารของ Apple ระบุว่าช่องคำสำคัญรับได้ "100 ไบต์" แต่ App Store Connect นับเป็นตัวอักษร
(ช่องภาษาญี่ปุ่นที่ยาว 100 ตัวอักษร / 220 ไบต์ บันทึกผ่านเมื่อ 2026-10-01)

## 0. ก่อนเริ่ม

- [ ] **PRE-01** เขียน **งานหลัก (jobs)** 3 อย่างที่แอปทำให้ผู้ใช้ ด้วยคำของผู้ใช้เอง ("หารบิลกับเพื่อน") พร้อมกลุ่มเป้าหมายและคู่แข่ง 5 อันดับแรก
- [ ] **PRE-02** เลือกตลาดหลัก: storefront / ประเทศ + ภาษา เรียงตามยอดติดตั้งปัจจุบันหรือจำนวนผู้ใช้เป้าหมาย
- [ ] **PRE-03** เก็บหน้าสโตร์ไว้ใน version control (เมตาดาต้าของ fastlane `deliver` / `supply`) เพื่อให้ดู diff ของทุกการเปลี่ยนแปลงได้
- [ ] **PRE-04** บันทึกค่าตั้งต้น (baseline) **ก่อน** เปลี่ยนอะไรก็ตาม: impressions จากการค้นหา, ยอดเข้าชมหน้าผลิตภัณฑ์, อัตรา conversion, ยอดดาวน์โหลดแยกตามแหล่งที่มา, คะแนนและจำนวนเรตติ้ง แยกตามประเทศหลัก (ดูหมวด 10)
- [ ] **PRE-05** มีบันทึกการเปลี่ยนแปลง (เช่น `docs/aso-log.md`): วันที่, ช่องที่เปลี่ยน, ก่อน → หลัง, ตัวชี้วัดที่ต้องดู, วันติดตามผล

## 1. ค้นคว้าคำสำคัญ

- [ ] **KW-01** คำตั้งต้น (seed) 5–10 คำ จากงานหลักและคำนามของหมวดหมู่ ไม่ใช่ชื่อแบรนด์ และไม่ใช่แค่ชื่อฟีเจอร์
- [ ] **KW-02** ขยายด้วย **autocomplete (คำแนะนำอัตโนมัติ)** ของแต่ละสโตร์เอง แยกตามตลาดและภาษา (ไล่ a–z เพื่อหา long-tail) ลำดับของคำแนะนำ = สัญญาณความนิยม
- [ ] **KW-03** อ่านชื่อ / ชื่อรองของคู่แข่ง 10 อันดับแรกในแต่ละคำหลัก (head term) และจดคำที่คู่แข่งใช้ร่วมกัน ห้ามใช้ชื่อแบรนด์ของคู่แข่ง
- [ ] **KW-04** ขุด **รีวิว** ของแอปเราและของคู่แข่ง เพื่อหาคำนามและคำกริยาที่ผู้ใช้ใช้จริง
- [ ] **KW-05** ให้คะแนนคำตัวเลือกทุกคำ: ความเกี่ยวข้อง (0–3 ตัดทิ้งถ้า < 2), ความนิยม (ตำแหน่งใน autocomplete หรือค่า popularity ของ Apple Ads), ความเปิดกว้าง / ความยาก (แอปใน 10 อันดับแรกเล็งคำนี้กี่แอป และแต่ละแอปแข็งแกร่งแค่ไหน)
- [ ] **KW-06** แอปใหม่หรือแอปเล็กให้เล็ง long-tail ที่ชนะได้ (3–4 คำ ความนิยมปานกลาง ความเปิดกว้างสูง) ก่อนคำหลัก
- [ ] **KW-07** มี **แผนผังคำสำคัญ (keyword map)** ต่อภาษา: กำหนดว่าคำใดอยู่ในชื่อแอป / ชื่อ, ชื่อรอง / คำอธิบายแบบย่อ และช่องคำสำคัญ / คำอธิบายแบบเต็ม ไม่มีคำที่ไร้ช่อง และไม่มีช่องที่ไร้คำ
- [ ] **KW-08** ระบุคำที่ติดอันดับ 11–50 อยู่แล้ว เพราะเป็นชัยชนะที่ได้มาง่ายที่สุด
- [ ] **KW-09** ค้นคว้าใหม่ **แยกตามตลาด** โดยค้นคำสำคัญเป็นภาษาท้องถิ่น ไม่ใช่แปลจากภาษาอังกฤษ

## 2. เมตาดาต้า App Store (ต่อภาษา)

- [ ] **AS-01** (auto) ชื่อแอป ≤ 30, ชื่อรอง ≤ 30, ช่องคำสำคัญ ≤ 100, ข้อความโปรโมต ≤ 170, คำอธิบาย ≤ 4000
- [ ] **AS-02** (auto) ชื่อแอป ชื่อรอง และช่องคำสำคัญ ใช้พื้นที่ไปแล้วช่องละ ≥ 90% ตัวอักษรที่เหลือว่างคือโอกาสติดอันดับที่เสียไป
- [ ] **AS-03** ชื่อแอป = แบรนด์ + คำที่สำคัญที่สุด และอ่านเป็นธรรมชาติ ("ชื่อแบรนด์: ติดตามนิสัย")
- [ ] **AS-04** (auto) ชื่อรองเพิ่มคำ **ใหม่** ไม่ซ้ำคำในชื่อแอปเลย
- [ ] **AS-05** (auto) ช่องคำสำคัญ: คั่นด้วยจุลภาค **ไม่เว้นวรรคหลังจุลภาค** และไม่มีจุลภาคปิดท้าย
- [ ] **AS-06** (auto) ช่องคำสำคัญไม่มีคำที่อยู่ในชื่อแอปหรือชื่อรองแล้ว และไม่มีคำซ้ำ
- [ ] **AS-07** (auto) ใช้รูปเอกพจน์ **หรือ** พหูพจน์อย่างใดอย่างหนึ่ง ไม่ใช่ทั้งสองแบบ
- [ ] **AS-08** (auto) ไม่มีคำที่เสียเปล่า: "app" (แอป), "apps", "free" (ฟรี), "iPhone", "iPad", "iOS", "Apple", ชื่อแบรนด์ / ชื่อบริษัท; (ตรวจเอง) ชื่อหมวดหมู่
- [ ] **AS-09** (auto, warning) ใช้คำเดี่ยวแทนวลี เพราะ Apple ผสมคำข้ามชื่อแอป + ชื่อรอง + ช่องคำสำคัญของภาษาเดียวกันให้เอง
- [ ] **AS-10** ไม่มีชื่อคู่แข่ง เครื่องหมายการค้า หรือชื่อคนดังในช่องใดเลย (แนวทางข้อ 2.3.7, 5.2.1)
- [ ] **AS-11** (auto) ไม่มีคำเรื่องราคา / อันดับ / คำกระตุ้นให้ลงมือ (call to action) ในชื่อแอป ชื่อรอง และคำสำคัญ: "free" (ฟรี), "best" (ดีที่สุด), "#1", "sale" (ลดราคา), "% off" (2.3.7) ไม่ว่าจะเป็นภาษาใด
- [ ] **AS-12** (auto) ไม่มีอีโมจิ และไม่ใช้เครื่องหมายการค้าของ Apple ราวกับเป็นส่วนหนึ่งของชื่อคุณ (iPhone, Siri…)
- [ ] **AS-13** **หมวดหมู่หลัก** คือหมวดที่เกี่ยวข้องที่สุด (มีผลต่อความเกี่ยวข้องของข้อความ) และตั้งหมวดหมู่รองแล้ว
- [ ] **AS-14** คำอธิบาย: 3 บรรทัดแรกบอกงานหลักและหลักฐาน ใช้บูลเล็ตที่กวาดตาอ่านง่าย ไม่ใช่ที่สำหรับใส่คำสำคัญ (ไม่ถูกทำดัชนีสำหรับการค้นหาใน App Store) แต่การค้นหาเว็บของ Google และตัวสร้างแท็กของ Apple อ่านส่วนนี้
- [ ] **AS-15** ใช้ข้อความโปรโมตกับข่าวหรือข้อเสนอล่าสุด (เปลี่ยนได้โดยไม่ต้องผ่านการตรวจ)
- [ ] **AS-16** (auto) URL นโยบายความเป็นส่วนตัวและ URL หน้าช่วยเหลือเป็น https; (ตรวจเอง) เปิดได้ทั้งสองลิงก์
- [ ] **AS-17** ชื่อที่แสดงของการซื้อในแอปบอกว่าผู้ใช้ได้อะไร และใส่คำค้นหาเมื่อเข้ากันได้อย่างเป็นธรรมชาติ ("ติดตามนิสัย Pro")
- [ ] **AS-18** อีเวนต์ในแอป (ถ้ามี): ใส่คำสำคัญในชื่ออีเวนต์ซึ่งยาวได้ 30 ตัวอักษร เผยแพร่พร้อมกันได้สูงสุด 10 รายการ
- [ ] **AS-19** **แท็กแอป (App tags)** (storefront สหรัฐฯ เมตาดาต้า en-US): ตรวจใน App Store Connect แล้ว และยกเลิกแท็กที่ผิด (คุณเพิ่มแท็กเองไม่ได้ จึงต้องเขียนคำอธิบาย en-US ให้บอกกรณีการใช้งานอย่างตรงไปตรงมา)
- [ ] **AS-20** ตอบแบบสอบถามการจัดเรตอายุตามระดับใหม่ปี 2025 แล้ว (4+ / 9+ / 13+ / 16+ / 18+)

## 3. เมตาดาต้า Google Play (ต่อภาษา)

- [ ] **GP-01** (auto) ชื่อ ≤ 30, คำอธิบายแบบย่อ ≤ 80, คำอธิบายแบบเต็ม ≤ 4000, มีอะไรใหม่ ≤ 500
- [ ] **GP-02** (auto) ชื่อและคำอธิบายแบบย่อใช้พื้นที่ไปแล้ว ≥ 90%
- [ ] **GP-03** ชื่อ = แบรนด์ + คำหลัก; คำอธิบายแบบย่อ = ประโยคที่สมบูรณ์หนึ่งประโยค มีคำรอง 2–3 คำและประโยชน์หลัก
- [ ] **GP-04** (auto) คำสำคัญในชื่อปรากฏในคำอธิบายแบบเต็ม และอยู่ภายใน ~300 ตัวอักษรแรก
- [ ] **GP-05** คำเป้าหมายแต่ละคำปรากฏอย่างเป็นธรรมชาติ 2–3 ครั้งในคำอธิบายแบบเต็ม ใช้คำที่เกี่ยวข้องและคำพ้องความหมาย ไม่เรียงรายการคำสำคัญ
- [ ] **GP-06** (auto) ไม่มีคำใดมีความหนาแน่นเกิน ~3% (การยัดคำสำคัญถือว่าละเมิดนโยบาย)
- [ ] **GP-07** (auto) ชื่อ / คำอธิบายแบบย่อ / ชื่อนักพัฒนา: ไม่มีอีโมจิ ไม่มีอักขระพิเศษซ้ำ ๆ (`!!!`, `★★`) ไม่มีคำที่เป็นตัวพิมพ์ใหญ่ทั้งหมด (ยกเว้นชื่อแบรนด์)
- [ ] **GP-08** (auto) ไม่มี "Free", "#1", "Best", "Top", "Popular", "New", "Editor's choice", "No ads" (ฟรี, ดีที่สุด, ท็อป, ยอดนิยม, ใหม่, ไม่มีโฆษณา) รวมถึงราคาหรือโปรโมชัน ในชื่อ ไอคอน หรือชื่อนักพัฒนา และต้องเป็นเช่นนี้ในทุกคำแปล
- [ ] **GP-09** ไม่มีคำรับรองที่ไม่ระบุแหล่งที่มา หรือคำพูดของผู้ใช้นิรนามในคำอธิบาย
- [ ] **GP-10** คำอธิบายแบบเต็มมีโครงสร้าง: ประโยคเปิดดึงความสนใจ (2 บรรทัด) → ฟีเจอร์หลักพร้อมหัวข้อ / บูลเล็ต → หลักฐาน → คำกระตุ้นให้ลงมือ ใช้ประโยคเรียบง่ายที่ LLM ยกไปอ้างได้ ("ใช้ X เพื่อ …") เพราะ Ask Play / AI highlights อ่านส่วนนี้
- [ ] **GP-11** ตั้งหมวดหมู่และ **แท็ก** สูงสุด 5 รายการแล้ว (ในหน้า Store settings)
- [ ] **GP-12** กรอกอีเมลติดต่อ เว็บไซต์ และนโยบายความเป็นส่วนตัวครบ และเว็บไซต์ก็อธิบายแอปด้วย (Ask Play อ่านเว็บไซต์นี้)
- [ ] **GP-13** กรอกแบบฟอร์มความปลอดภัยของข้อมูล (Data safety) ครบและตรงกับการทำงานจริงของแอป

## 4. การแปลและปรับตามท้องถิ่น

- [ ] **L10N-01** ตลาดหลักทุกแห่งมีหน้าสโตร์ของตัวเอง ไม่ใช่คำแปลอัตโนมัติของ Play และไม่ใช่ภาษาอังกฤษ
- [ ] **L10N-02** (auto) ช่องคำสำคัญ / คำอธิบายแบบย่อ **ไม่ได้คัดลอก** มาจากภาษาต้นทาง (base locale)
- [ ] **L10N-03** ใช้คำค้นหาท้องถิ่นที่ได้จาก autocomplete ในท้องถิ่นและคู่แข่งในท้องถิ่น (KW-09)
- [ ] **L10N-04** **cross-localization** ของ App Store: สำหรับ storefront หลักแต่ละประเทศ ให้ระบุภาษาเพิ่มเติมที่ Apple ทำดัชนีในประเทศนั้น (US: en-US + es-MX, ar, zh-Hans, zh-Hant, fr-FR, ko, pt-BR, ru, vi; UK: en-GB; CA: en-CA + fr-CA; JP: ja + en-US; ประเทศอื่นส่วนใหญ่: ภาษาท้องถิ่น + en-GB) และใส่คำในช่องคำสำคัญที่ **ไม่ซ้ำกัน** ให้แต่ละภาษา
- [ ] **L10N-05** ภาษาที่ใช้ทำ cross-localization ยังต้องอ่านถูกต้องสำหรับเจ้าของภาษานั้น (ผู้ใช้จริงเห็นข้อความเหล่านี้)
- [ ] **L10N-06** (auto) หน้าสโตร์ภาษา CJK / ไทย / อาหรับ ก็ต้องเติมให้เต็มขีดจำกัดเช่นกัน ช่องที่สั้นเกินไปในภาษาเหล่านี้คือการสูญเปล่าที่พบบ่อยที่สุด
- [ ] **L10N-07** แปลภาพหน้าจอและคำบรรยายภาพสำหรับภาษาหลัก และใช้เลย์เอาต์ขวาไปซ้ายสำหรับภาษาอาหรับ / ฮีบรู
- [ ] **L10N-08** ตรวจคำกล่าวอ้างในภาษาท้องถิ่นด้วย ("miễn phí", "gratis", "無料", "무료", "免费"…)

## 5. ไอคอน ภาพหน้าจอ วิดีโอ

- [ ] **CR-01** ไอคอน: สัญลักษณ์ชัดเจนเพียงหนึ่งเดียว ไม่มีตัวหนังสือ มองออกที่ขนาด 40 px และแตกต่างจากไอคอนของคู่แข่ง 10 อันดับแรกเมื่อวางเทียบกัน
- [ ] **CR-02** iOS 26: ตรวจไอคอน Liquid Glass แบบเลเยอร์ในโหมดสว่าง มืด แต่งสี (tinted) และใส (clear) แล้ว
- [ ] **CR-03** (auto, Play) ไอคอน PNG 512×512; กราฟิกเด่น (feature graphic) 1024×500 ไม่มี alpha และไม่อ้างอันดับ / ราคา / รางวัล
- [ ] **CR-04** ภาพหน้าจอที่ 1 แสดง **งานหลัก** พร้อมคำหลักในคำบรรยาย ≤ 5 คำ และสื่อสารได้ด้วยตัวเองในผลการค้นหา
- [ ] **CR-05** ภาพหน้าจอที่ 2–3 แสดงเหตุผลอีกสองข้อที่ควรติดตั้ง หนึ่งภาพต่อหนึ่งประโยชน์
- [ ] **CR-06** ใช้ UI จริงของแอป (App Store 2.3.3); คำบรรยายบน Play ≤ 20% ของภาพ; ไม่มี "Download now" (ดาวน์โหลดเลย), "#1", "Best" (ดีที่สุด) หรือป้ายสโตร์
- [ ] **CR-07** App Store: ชุด iPhone 6.9" (1320×2868 / 1290×2796 / 1260×2736) และชุด iPad 13" (2064×2752 / 2048×2732) หากแอปรันบน iPad ได้ สูงสุดชุดละ 10 ภาพ ไม่มี alpha
- [ ] **CR-08** (auto) Play: ภาพหน้าจอโทรศัพท์ 2–8 ภาพ แต่ละด้าน 320–3840 px ด้านยาว ≤ 2× ด้านสั้น; ต้องมี ≥ 4 ภาพที่ ≥ 1080 px (9:16 หรือ 16:9) จึงมีสิทธิ์ได้รับการแนะนำ (featuring); มีชุดแท็บเล็ต / Chromebook / Wear หากรองรับ (แสดงแยกตามประเภทอุปกรณ์)
- [ ] **CR-09** วิดีโอ (ไม่บังคับ แต่ควรทดสอบ): ตัวอย่างแอป (app preview) ของ App Store ยาว 15–30 วินาที ใช้ภาพบันทึกหน้าจอเท่านั้น 3 วินาทีแรกต้องสื่องานหลักได้โดยไม่มีเสียง; ลิงก์ YouTube ของ Play ตั้งเป็นสาธารณะ / ไม่เป็นสาธารณะ (unlisted) ปิดโฆษณา และ 30 วินาทีแรกสำคัญที่สุด
- [ ] **CR-10** ภาพและวิดีโอสอดคล้องกับแผนผังคำสำคัญ: สิ่งที่คนค้นหาคือสิ่งที่ภาพหน้าจอที่ 1 แสดง

## 6. หน้าแบบกำหนดเองและการทดลอง

- [ ] **EXP-01** **หน้าผลิตภัณฑ์แบบกำหนดเอง (custom product pages)** ของ App Store (สูงสุด 70 หน้า) สำหรับเจตนาการค้นหาหลัก แต่ละหน้ากำหนดคำสำคัญจากช่องคำสำคัญที่ผ่านการอนุมัติแล้ว
- [ ] **EXP-02** **หน้าสโตร์แบบกำหนดเอง (custom store listings)** ของ Google Play (สูงสุด 50 หน้า) สำหรับคำค้นหามูลค่าสูง / ประเทศ / ผู้ใช้ที่เลิกใช้ไปแล้ว
- [ ] **EXP-03** ต้องมีการทดลองหนึ่งรายการรันอยู่เสมอในตลาดที่สำคัญที่สุด: การปรับหน้าผลิตภัณฑ์ให้เหมาะสม (product page optimization) ของ App Store (≤ 3 ทรีตเมนต์, ≤ 90 วัน) หรือการทดลองหน้าสโตร์ (store listing experiments) ของ Play (≤ 2 เวอร์ชัน; ทดสอบชื่อและวิดีโอไม่ได้)
- [ ] **EXP-04** ทุกการทดสอบ: ตัวแปรเดียว มีสมมติฐานเป็นลายลักษณ์อักษร มีตัวชี้วัดความสำเร็จ รัน ≥ 7 วัน และหยุดเมื่อคอนโซลบอกว่าถึงระดับความเชื่อมั่นแล้วเท่านั้น
- [ ] **EXP-05** ลำดับการทดสอบตามผลที่คาดว่าจะเพิ่มขึ้น: ไอคอน → ภาพหน้าจอที่ 1 → คำบรรยายภาพ → ลำดับภาพหน้าจอ → วิดีโอ
- [ ] **EXP-06** บันทึกผล (ชนะ / แพ้ / ไม่ต่าง) และนำตัวที่ชนะไปใช้กับภาษาอื่นในรูปแบบการทดสอบใหม่ ไม่ใช่ทึกทักเอาเองว่าได้ผล

## 7. คะแนนและรีวิว

- [ ] **RV-01** ใช้หน้าต่างขอรีวิวในแอปแบบเนทีฟ (`requestReview` / Play In-App Review API) หลังผู้ใช้ทำสิ่งใดสำเร็จ ห้ามขอตอนเปิดแอป หลังเกิดข้อผิดพลาด หรือคัดกรองให้เฉพาะผู้ใช้ที่พอใจ (gating) และห้ามให้สิ่งจูงใจ
- [ ] **RV-02** คะแนนเฉลี่ย ≥ 4.0 ในทุกประเทศหลัก (Play คิดคะแนนแยกตามประเทศและประเภทอุปกรณ์ และให้น้ำหนักคะแนนล่าสุดมากกว่า)
- [ ] **RV-03** ตอบรีวิว 1–3★ ภายในไม่กี่วันอย่างเจาะจง และตอบอีกครั้งเมื่อปล่อยการแก้ไขแล้ว
- [ ] **RV-04** รู้ว่าข้อร้องเรียนที่พบซ้ำบ่อยที่สุดคืออะไรและใส่ไว้ในโรดแมปแล้ว เพราะสรุปรีวิวด้วย AI ของทั้งสองสโตร์จะดึงเรื่องนี้ขึ้นเป็นหัวข้อ
- [ ] **RV-05** ขุดข้อความรีวิวทุกเดือน เพื่อหาคำสำคัญใหม่และคำขอฟีเจอร์

## 8. คุณภาพและสัญญาณทางเทคนิค

- [ ] **Q-01** Android vitals ของ Play ต่ำกว่าเกณฑ์พฤติกรรมไม่ดี (28 วัน): อัตราแครชที่ผู้ใช้รับรู้ < 1.09%, ANR < 0.47%, ต่อรุ่นโทรศัพท์ < 8%; partial wake lock ที่มากเกินไป < 5% ของเซสชัน
- [ ] **Q-02** วางแผนรับมือเกณฑ์หน่วยความจำ / bitmap / DEX ของ Play ที่จะบังคับใช้ในเดือนกุมภาพันธ์ 2027
- [ ] **Q-03** Play: target API 36 สำหรับแอปใหม่ / อัปเดต (ตั้งแต่ 2026-08-31); Apple: บิลด์ด้วย SDK ของ Xcode 26 (ตั้งแต่ 2026-04-28)
- [ ] **Q-04** อัปเดตแอปอย่างน้อยทุก 1–3 เดือน และ "มีอะไรใหม่" (What's New) อธิบายการเปลี่ยนแปลงจริง (2.3.12)
- [ ] **Q-05** ขนาดดาวน์โหลดเล็ก ไม่แครชตอนเปิดครั้งแรก และไม่บังคับเข้าสู่ระบบก่อนผู้ใช้เห็นคุณค่าของแอป
- [ ] **Q-06** ประกาศป้ายข้อมูลความเป็นส่วนตัว (privacy nutrition label) / ความปลอดภัยของข้อมูล และ (ไม่บังคับ, App Store) Accessibility Nutrition Labels แล้ว

## 9. นโยบาย — ป้องกันการถูกปฏิเสธและถูกนำออกจากสโตร์

- [ ] **POL-01** ไม่มีคำกล่าวอ้างที่ทำให้เข้าใจผิด รีวิวปลอม "#1" / "best" ที่พิสูจน์ไม่ได้ หรือราคาในชื่อแอป / ชื่อ (App Store 2.3.1, 2.3.7; นโยบายเมตาดาต้าของ Play)
- [ ] **POL-02** ไม่มีชื่อแพลตฟอร์มอื่นในเมตาดาต้า App Store ("Android", "Google Play") (2.3.10)
- [ ] **POL-03** ไม่มีเครื่องหมายการค้าของบุคคลที่สามหรือชื่อที่เลียนแบบ (5.2.1; นโยบายการแอบอ้างเป็นผู้อื่นของ Play)
- [ ] **POL-04** ใช้ "For Kids" / "For Children" (สำหรับเด็ก) ได้เฉพาะในหมวดหมู่ Kids (2.3.8)
- [ ] **POL-05** ภาพหน้าจอ / วิดีโอตัวอย่าง: แสดงแอปขณะใช้งาน ไม่ใช่แค่หน้า splash หรือหน้าเข้าสู่ระบบ (2.3.3, 2.3.4)
- [ ] **POL-06** ทุกคำแปลทำตามกฎเดียวกัน (Play บังคับใช้นโยบายแยกตามภาษา)

## 10. วัดผลและปรับปรุงต่อเนื่อง

- [ ] **M-01** App Store Connect → Analytics: impressions จาก App Store Search, ยอดเข้าชมหน้าผลิตภัณฑ์, conversion, ยอดดาวน์โหลด แยกตามประเทศและตามหน้าผลิตภัณฑ์แบบกำหนดเอง
- [ ] **M-02** Play Console → Grow overview / Statistics: การได้ผู้ใช้ใหม่ (acquisition) แยกตาม **คำค้นหา** และแหล่งที่มาของทราฟฟิก (Store analysis ถูกปลดระวางในเดือนมิถุนายน 2026 และตัวชี้วัดหน้าสโตร์เปลี่ยนไปนับเป็น unique user clicks ในเดือนกรกฎาคม 2026 อย่าเปรียบเทียบข้อมูลข้ามช่วงนั้น)
- [ ] **M-03** ติดตามอันดับของคำสำคัญในแผนผังคำสำคัญ (เครื่องมือติดตามอันดับ, รายงานคำค้นหาของ Apple Ads หรือไล่ autocomplete ใหม่ทุกเดือน)
- [ ] **M-04** เปลี่ยนทีละกลุ่มช่อง รอ 2–4 สัปดาห์ก่อนตัดสินผล; ชื่อแอป / ชื่อรอง / คำสำคัญของ App Store เปลี่ยนได้เฉพาะพร้อมเวอร์ชันใหม่เท่านั้น
- [ ] **M-05** ทุกเดือน: ตัดคำในช่องคำสำคัญที่ไม่มี impressions หลังผ่านไป 4–6 สัปดาห์ เพิ่มคำตัวเลือกถัดไป และตรวจคู่แข่งกับฤดูกาลอีกครั้ง
