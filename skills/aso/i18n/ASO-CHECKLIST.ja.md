## AI エージェントへ：まずここを読む

1. **デフォルトは監査モード。** ストア掲載情報を読み、以下の全項目に印を付けて報告する。ファイルを編集するのは、ユーザーが修正を頼んだときだけ。この会話でユーザーが頼んでいない限り、**App Store Connect /
   Play Console へのアップロードや審査への提出は決してしない**。
2. **ストア掲載情報を見つける。** fastlane なら `fastlane/metadata/ios/<locale>/*.txt`（または
   `fastlane/metadata/<locale>/`）と `fastlane/metadata/android/<locale>/*.txt`。見つからなければ、言語ごとのアプリ名 / サブタイトル / キーワード / 概要、または Play のタイトル / 簡単な説明 / 詳しい説明を貼り付けてもらうようユーザーに頼む。
3. **文字数は目で数えず、必ずコードで数える。** **(auto)** の付いた項目は、無料のスクリプトでチェックできる：
   ```bash
   curl -sSLO https://raw.githubusercontent.com/shipflutter/skills/develop/skills/aso/scripts/aso_check.py
   python3 aso_check.py --root .            # markdown report; exit 1 on errors
   curl -sSLO https://raw.githubusercontent.com/shipflutter/skills/develop/skills/aso/scripts/keyword_suggest.py
   python3 keyword_suggest.py "habit tracker" --az --country us --competition
   ```
   （Python 3.10+、標準ライブラリのみ、API キー不要。）
4. **各項目に印を付ける：** `✅ pass` / `⚠️ improve` / `❌ fail` / `N/A`（合格 / 要改善 / 不合格 / 対象外）。根拠（ファイル、文字数、引用）も添える。
   ⚠️/❌ にはすべて、上限内に収まる具体的な修正案を付ける。最後のレポートテンプレートを使う。
5. **データを捏造しない。** 自分で計測していない検索ボリューム、順位、評価は書かない。代わりに「未計測」（not measured）と書く。以下で UNCONFIRMED と記された事実はツールベンダーの観測であり、ストアのルールではない。

## 上限の早見表

| ストア | 項目 | 上限 | 検索のインデックス対象 |
|---|---|---|---|
| App Store | アプリ名 | 30 | ✅ 最も強い |
| App Store | サブタイトル | 30 | ✅ |
| App Store | キーワード項目（非公開） | 100 | ✅ |
| App Store | プロモーションテキスト | 170 | ❌（審査なしで編集できる） |
| App Store | 概要 | 4000 | ❌ App Store 検索では対象外 |
| App Store | このバージョンの新機能 | 4000 | ❌ |
| App Store | App内イベント（in-app events）の名前 / 短い説明 / 詳しい説明 | 30 / 50 / 120 | ✅ イベント名 |
| App Store | App内課金の表示名 / 説明 | 30 / 45 | ✅ プロモーション中の App内課金 |
| Google Play | タイトル | 30 | ✅ 最も強い |
| Google Play | 簡単な説明 | 80 | ✅ |
| Google Play | 詳しい説明 | 4000 | ✅（非公開のキーワード項目はない） |
| Google Play | リリースノート | 500 | ❌ |

Apple のドキュメントではキーワード項目は「100 バイト」とされているが、App Store Connect
は文字数で数える（2026-10-01 に、100 文字 / 220 バイトの日本語キーワード項目が受け付けられた）。

## 0. 始める前に

- [ ] **PRE-01** アプリの中核となる **ジョブ**（ユーザーがアプリで片付けたい用事）を 3 つ、ユーザーの言葉で書き出す（「友だちと割り勘する」など）。対象ユーザーと、主な競合アプリ上位 5 つも書く。
- [ ] **PRE-02** 優先市場を決める：ストアフロント / 国 + 言語を、現在のインストール数または狙うユーザー数の順に並べる。
- [ ] **PRE-03** ストア掲載情報をバージョン管理に置き（fastlane `deliver` / `supply` のメタデータ）、すべての変更を diff で確認できる。
- [ ] **PRE-04** 変更の**前に**ベースラインを記録している：検索インプレッション、プロダクトページの閲覧数、コンバージョン率、流入元ごとのダウンロード数、評価と評価件数を、優先国ごとに（セクション 10 を参照）。
- [ ] **PRE-05** 変更ログがある（例：`docs/aso-log.md`）：日付、変更した項目、変更前 → 変更後、確認する指標、再確認の日付。

## 1. キーワードリサーチ

- [ ] **KW-01** ジョブとカテゴリの名詞から、シードキーワードを 5–10 個選ぶ。ブランド名は入れず、機能名だけにも偏らない。
- [ ] **KW-02** 各ストアの **オートコンプリート**（検索候補）で、市場・言語ごとに広げる（a–z を付けてロングテールを集める）。候補の並び順 = 人気度のシグナル。
- [ ] **KW-03** ビッグキーワードごとに、上位 10 位の競合のタイトル / サブタイトルを読み、共通する単語を書き留める。競合のブランド名は決して使わない。
- [ ] **KW-04** 自分のアプリと競合の **レビュー** から、ユーザーが実際に使う名詞と動詞を拾い出す。
- [ ] **KW-05** 候補ごとにスコアを付ける：関連性（0–3、< 2 は除外）、人気度（オートコンプリートでの順位、または Apple Ads の人気度）、参入余地 / 難易度（上位 10 アプリのうち何本が狙っているか、それらがどれほど強いか）。
- [ ] **KW-06** 新しいアプリや小規模なアプリは、ビッグキーワードより先に、勝てるロングテール（3–4 語、人気度は中程度、参入余地が大きい）を狙う。
- [ ] **KW-07** 言語ごとの **キーワードマップ**：アプリ名 / タイトル、サブタイトル / 簡単な説明、キーワード項目 / 詳しい説明が、それぞれどのキーワードを受け持つか。置き場所のないキーワードも、キーワードのない置き場所も作らない。
- [ ] **KW-08** すでに 11–50 位にいるキーワードを洗い出している。最も低コストで狙える成果。
- [ ] **KW-09** リサーチは**市場ごとに**やり直す。キーワードは英語から翻訳せず、現地の言語でリサーチする。

## 2. App Store のメタデータ（言語ごと）

- [ ] **AS-01** (auto) アプリ名 ≤ 30、サブタイトル ≤ 30、キーワード項目 ≤ 100、プロモーションテキスト ≤ 170、概要 ≤ 4000。
- [ ] **AS-02** (auto) アプリ名、サブタイトル、キーワード項目をそれぞれ ≥ 90% まで埋めている。空いた文字数は、そのまま順位の取りこぼしになる。
- [ ] **AS-03** アプリ名 = ブランド名 + 最優先のキーワードで、自然に読める（「ブランド名：習慣トラッカー」）。
- [ ] **AS-04** (auto) サブタイトルで**新しい**単語を加える。アプリ名の単語は繰り返さない。
- [ ] **AS-05** (auto) キーワード項目：カンマ（,）区切り、**カンマの後にスペースなし**、末尾にカンマなし。
- [ ] **AS-06** (auto) キーワード項目に、アプリ名やサブタイトルにすでにある単語も、重複もない。
- [ ] **AS-07** (auto) 単数形**か**複数形のどちらか一方だけ。両方は入れない。
- [ ] **AS-08** (auto) 無駄な単語がない："app"、"apps"（アプリ）、"free"（無料）、"iPhone"、"iPad"、"iOS"、"Apple"、ブランド名 / 会社名。（手動）カテゴリ名も。
- [ ] **AS-09** (auto, warning) フレーズより単語単位で入れる。Apple は同じ言語のアプリ名 + サブタイトル + キーワード項目をまたいで単語を組み合わせる。
- [ ] **AS-10** 競合の名前、商標、著名人の名前をどこにも使わない（ガイドライン 2.3.7、5.2.1）。
- [ ] **AS-11** (auto) アプリ名、サブタイトル、キーワードには、どの言語でも価格 / ランキング / 行動喚起の言葉を入れない（2.3.7）："free"（無料）、"best"（最高）、"#1"、"sale"（セール）、"% off"（% オフ）。
- [ ] **AS-12** (auto) 絵文字なし。Apple の商標（iPhone、Siri…）を、自分のアプリ名の一部のように使わない。
- [ ] **AS-13** **プライマリカテゴリ**は最も関連の深いものにする（テキストの関連性の評価に含まれる）。セカンダリカテゴリも設定する。
- [ ] **AS-14** 概要：最初の 3 行で主なジョブとその裏付けを示す。流し読みできる箇条書きにする。キーワード目的には使わない（App Store 検索のインデックス対象外）が、Google のウェブ検索と Apple のタグ生成には読まれる。
- [ ] **AS-15** プロモーションテキストを最新のお知らせ / キャンペーンに使う（審査なしで変更できる）。
- [ ] **AS-16** (auto) プライバシーポリシーの URL とサポート URL が https。（手動）どちらも開ける。
- [ ] **AS-17** App内課金の表示名で、ユーザーが得られるものを説明し、自然に入るなら検索キーワードも含める（「習慣トラッカー Pro」）。
- [ ] **AS-18** App内イベント（ある場合）：30 文字のイベント名にキーワードを入れる。同時に公開できるのは最大 10 件。
- [ ] **AS-19** **App タグ**（App tags。米国のストアフロント、en-US のメタデータが対象）：App Store Connect で確認し、間違ったタグの選択を外す（タグは追加できないので、en-US の概要に用途をはっきり書く）。
- [ ] **AS-20** 年齢制限指定の質問票に、2025 年版の区分（4+ / 9+ / 13+ / 16+ / 18+）で回答している。

## 3. Google Play のメタデータ（言語ごと）

- [ ] **GP-01** (auto) タイトル ≤ 30、簡単な説明 ≤ 80、詳しい説明 ≤ 4000、リリースノート ≤ 500。
- [ ] **GP-02** (auto) タイトルと簡単な説明を ≥ 90% まで埋めている。
- [ ] **GP-03** タイトル = ブランド名 + ビッグキーワード。簡単な説明 = サブキーワード 2–3 個と主なメリットを含む、文として成り立つ一文。
- [ ] **GP-04** (auto) タイトルのキーワードが詳しい説明に含まれ、しかも冒頭の約 300 文字以内に出てくる。
- [ ] **GP-05** 狙うキーワードは、それぞれ詳しい説明に自然な形で 2–3 回出す。関連語や類義語も使う。キーワードの羅列はしない。
- [ ] **GP-06** (auto) 出現率が約 3% を超える単語がない（キーワードの詰め込みはポリシー違反）。
- [ ] **GP-07** (auto) タイトル / 簡単な説明 / デベロッパー名：絵文字なし、特殊文字の連続（`!!!`、`★★`）なし、すべて大文字（ALL CAPS）の単語なし（ブランド名なら可）。
- [ ] **GP-08** (auto) タイトル、アイコン、デベロッパー名に "Free"、"#1"、"Best"、"Top"、"Popular"、"New"、"Editor's choice"、"No ads"、価格、プロモーションを入れない（「無料」「最高」「人気」「新着」「広告なし」なども同様）。すべての翻訳で守る。
- [ ] **GP-09** 説明文に、出典のない推薦文や匿名ユーザーの声を載せない。
- [ ] **GP-10** 詳しい説明に構成がある：つかみ（2 行）→ 見出し / 箇条書きで主な機能 → 裏付け → 行動喚起。Ask Play や AI ハイライトが読むので、LLM がそのまま引用できる平易な文で書く（「X で…できます」）。
- [ ] **GP-11** カテゴリと最大 5 個の **タグ** を設定している（ストアの設定）。
- [ ] **GP-12** 連絡先のメールアドレス、ウェブサイト、プライバシーポリシーを入力している。ウェブサイトでもアプリを説明する（Ask Play はウェブサイトも読む）。
- [ ] **GP-13** データ セーフティ（Data safety）のフォームをすべて記入し、アプリの実際の動作と一致している。

## 4. ローカライズ

- [ ] **L10N-01** 優先市場ごとに専用のストア掲載情報がある。Play の自動翻訳でも、英語のままでもない。
- [ ] **L10N-02** (auto) キーワード項目 / 簡単な説明を、基準言語から**コピーしていない**。
- [ ] **L10N-03** 現地のオートコンプリートと現地の競合から、現地の検索語句を集める（KW-09）。
- [ ] **L10N-04** App Store の **クロスローカライズ**：優先するストアフロントごとに、Apple がそこで追加でインデックスする言語を書き出し（US: en-US + es-MX, ar, zh-Hans, zh-Hant, fr-FR, ko, pt-BR, ru, vi; UK: en-GB; CA: en-CA + fr-CA; JP: ja + en-US; その他の大半: 現地語 + en-GB）、言語ごとに**異なる**単語をキーワード項目に入れる。
- [ ] **L10N-05** クロスローカライズに使う言語の掲載情報も、その言語のネイティブが読んで正しく通じる（実際のユーザーが目にする）。
- [ ] **L10N-06** (auto) CJK / タイ語 / アラビア語のストア掲載情報も上限まで埋める。これらの言語では、短いまま残った項目が最もよくある無駄。
- [ ] **L10N-07** 優先言語のスクリーンショットとキャプションをローカライズしている。アラビア語 / ヘブライ語は右から左（RTL）のレイアウト。
- [ ] **L10N-08** 誇大表現を現地の言語でもチェックしている（"miễn phí", "gratis", "無料", "무료", "免费"…）。

## 5. アイコン、スクリーンショット、動画

- [ ] **CR-01** アイコン：明確なシンボルがひとつ、文字なし、40 px でも判別できる、上位 10 の競合アイコンと並べても区別がつく。
- [ ] **CR-02** iOS 26：レイヤー構造の Liquid Glass アイコンを、ライト、ダーク、色合い（tinted）、クリアの各モードで確認している。
- [ ] **CR-03** (auto, Play) アイコンは 512×512 の PNG。フィーチャーグラフィックは 1024×500 でアルファなし、ランキング / 価格 / 受賞のアピールなし。
- [ ] **CR-04** 1 枚目のスクリーンショットで**主なジョブ**を見せ、ビッグキーワードを ≤ 5 語のキャプションに入れる。検索結果に単独で表示されても伝わる。
- [ ] **CR-05** 2–3 枚目のスクリーンショットで、インストールしたくなる次の理由をふたつ見せる。スクリーンショットごとにメリットはひとつ。
- [ ] **CR-06** 実際のアプリの UI を使う（App Store 2.3.3）。Play のキャプションは画像の ≤ 20%。"Download now"（今すぐダウンロード）、"#1"、"Best"（最高）、ストアのバッジは入れない。
- [ ] **CR-07** App Store：6.9 インチ iPhone 用のセット（1320×2868 / 1290×2796 / 1260×2736）と、iPad で動くなら 13 インチ iPad 用のセット（2064×2752 / 2048×2732）。それぞれ最大 10 枚、アルファなし。
- [ ] **CR-08** (auto) Play：スマートフォンのスクリーンショット 2–8 枚、各辺 320–3840 px、長辺 ≤ 短辺の 2 倍。おすすめ掲載の対象になるには ≥ 1080 px のものを ≥ 4 枚（9:16 または 16:9）。対応していればタブレット / Chromebook / Wear 用のセットも用意する（フォームファクタごとに表示される）。
- [ ] **CR-09** 動画（任意。効果はテストで確かめる）：App Store のプレビューは 15–30 秒、画面収録のみ、最初の 3 秒で音なしでもジョブが伝わる。Play の YouTube リンクは公開 / 限定公開、広告はオフ、最初の 30 秒が勝負。
- [ ] **CR-10** クリエイティブがキーワードマップと一致している：ユーザーが検索したものを、1 枚目のスクリーンショットで見せる。

## 6. カスタムページと実験

- [ ] **EXP-01** App Store の **カスタムプロダクトページ**（custom product pages、最大 70）を主要なキーワードの検索意図ごとに作り、それぞれに承認済みのキーワード項目からキーワードを割り当てる。
- [ ] **EXP-02** Google Play の **カスタムストア掲載情報**（custom store listings、最大 50）を、価値の高い検索キーワード / 国 / 離脱ユーザー向けに作る。
- [ ] **EXP-03** 最重要の市場で常に実験をひとつ回す：App Store のプロダクトページの最適化（product page optimization、≤ 3 案、≤ 90 日）または Play のストア掲載情報のテスト（store listing experiments、≤ 2 バリアント。タイトルと動画はテストできない）。
- [ ] **EXP-04** 各テスト：変数はひとつ、仮説を文章にする、成功指標を決める、≥ 7 日、止めるのはコンソールが示す信頼度に達したときだけ。
- [ ] **EXP-05** 期待できる効果の大きい順にテストする：アイコン → 1 枚目のスクリーンショット → キャプション → スクリーンショットの順番 → 動画。
- [ ] **EXP-06** 結果を記録し（勝ち / 負け / 差なし）、勝った案は他の言語にそのまま当てはめず、新しいテストとして試す。

## 7. 評価とレビュー

- [ ] **RV-01** ネイティブのアプリ内レビュー依頼（`requestReview` / Play In-App Review API）を、成功体験の直後に出す。起動直後やエラーの後には出さず、満足度で振り分けるゲーティングもしない。見返りも付けない。
- [ ] **RV-02** 優先国ごとに平均評価 ≥ 4.0（Play の評価は国とフォームファクタごとに分かれ、最近の評価ほど重みが大きい）。
- [ ] **RV-03** 1–3★ のレビューには数日以内に具体的に返信する。修正をリリースしたら改めて返信する。
- [ ] **RV-04** 最も多い不満を把握し、ロードマップに載せている。両ストアの AI によるレビュー要約は、それを見出しとして表示する。
- [ ] **RV-05** 毎月レビュー本文を分析し、新しいキーワードと機能要望を拾う。

## 8. 品質と技術的シグナル

- [ ] **Q-01** Play の Android vitals が不正な動作のしきい値を下回っている（28 日間）：ユーザーが認識したクラッシュ率 < 1.09%、ANR < 0.47%、スマートフォンのモデル別 < 8%。過剰な部分的ウェイクロック < セッションの 5%。
- [ ] **Q-02** 2027 年二月に適用予定の Play のメモリ / ビットマップ / DEX のしきい値に備えている。
- [ ] **Q-03** Play：新規アプリ / アップデートはターゲット API 36（2026-08-31 から）。Apple：Xcode 26 SDK でビルドする（2026-04-28 から）。
- [ ] **Q-04** 少なくとも 1–3 か月ごとにアップデートする。このバージョンの新機能（What's New）には実際の変更を書く（2.3.12）。
- [ ] **Q-05** ダウンロードサイズを小さく保つ。初回起動でクラッシュせず、価値を見せる前にサインインの壁を置かない。
- [ ] **Q-06** プライバシー栄養ラベル / データ セーフティと、（任意、App Store）アクセシビリティ栄養ラベル（Accessibility Nutrition Labels）を申告している。

## 9. ポリシー：リジェクト・削除を防ぐチェック

- [ ] **POL-01** 誤解を招く表現、偽のレビュー、検証できない "#1" / "best"、アプリ名 / タイトル内の価格がない（App Store 2.3.1、2.3.7、Play のメタデータ ポリシー）。
- [ ] **POL-02** App Store のメタデータに他のプラットフォーム名（"Android"、"Google Play"）がない（2.3.10）。
- [ ] **POL-03** 第三者の商標や、他のアプリをまねた名前がない（5.2.1、Play のなりすましに関するポリシー）。
- [ ] **POL-04** "For Kids" / "For Children"（キッズ向け / 子ども向け）はキッズカテゴリでのみ使う（2.3.8）。
- [ ] **POL-05** スクリーンショット / プレビュー：使用中のアプリを見せる。スプラッシュ画面やログイン画面だけにしない（2.3.3、2.3.4）。
- [ ] **POL-06** すべての翻訳が同じルールに従う（Play はポリシーを言語ごとに適用する）。

## 10. 計測と改善

- [ ] **M-01** App Store Connect → アナリティクス（Analytics）：App Store 検索のインプレッション、プロダクトページの閲覧数、コンバージョン、ダウンロード数を、国ごと・カスタムプロダクトページごとに見る。
- [ ] **M-02** Play Console → Grow overview / Statistics（統計情報）：**検索語句**別・トラフィックソース別の獲得数（Store analysis は 2026 年六月に廃止。掲載情報の指標は 2026 年七月にユニークユーザーのクリック数ベースに変わったので、その時点をまたいで比較しない）。
- [ ] **M-03** キーワードマップのキーワードの順位を追跡する（ランクトラッカー、Apple Ads の検索語句レポート、または毎月のオートコンプリート再調査）。
- [ ] **M-04** 一度に変えるのはひとつの項目グループだけ。判断する前に 2–4 週間待つ。App Store のアプリ名 / サブタイトル / キーワードは、新しいバージョンでしか変更できない。
- [ ] **M-05** 毎月：4–6 週間たってもインプレッションのないキーワード項目の単語を外し、次の候補を加え、競合と季節性を見直す。
