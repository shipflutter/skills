# EP01.US001 — One-Command Multi-Platform Release Pipeline

## Summary

As a **mobile developer**, I want to run a single shell script that builds and deploys ShipFlutter to all distribution channels — iOS TestFlight, Android Firebase App Distribution, and Google Play Store (internal testing) — with Telegram notifications, so that I can ship new versions to testers with zero manual steps.

## Actors

| Actor | Role |
|-------|------|
| **Mobile Developer** | Runs `deploy.sh` / `prod.sh` locally |
| **CI/CD Pipeline** | GitHub Actions triggers deploy on merge to `uat` |
| **QA/Tester** | Receives build via Firebase App Distribution, TestFlight, or Play Store internal testing |
| **Release Manager** | Runs `prod.sh` for internal testing releases on all platforms |

## User Stories

| ID | Story | Priority |
|----|-------|----------|
| US001 | Run `./deploy.sh` to build + deploy iOS to TestFlight | P0 |
| US002 | Run `./deploy.sh android` to build + deploy Android to Firebase | P0 |
| US003 | Run `./prod.sh` to deploy both platforms to internal testing (Play Store internal track) | P0 |
| US004 | Receive Telegram notification when build starts/completes/fails | P1 |
| US005 | Auto-trigger deploy on merge to `uat` via GitHub Actions (includes Play Store internal) | P1 |
| US006 | Run `./deploy.sh` to deploy both platforms in one command | P1 |
| US007 | Generate all GitHub secrets from local assets via `scripts/prepare.sh` | P2 |
| US008 | Android AAB uploaded to Google Play Store internal testing track | P2 |

## Main Flow

1. Developer runs `./deploy.sh [ios|android|all]` or `./prod.sh`.
2. Script sources `.env.prod` for all credentials and paths.
3. Script parses `version: X.Y.Z+N` from `pubspec.yaml`.
4. **Android pipeline**:
   - Creates `android/key.properties` from keystore in `.app_dist/`
   - `flutter build apk --release` → Firebase App Distribution
   - `flutter build appbundle --release` → Google Play Store (internal testing track)
5. **iOS pipeline**:
   - Imports P12 + WWDR cert into temp keychain
   - Installs provisioning profile
   - Patches Xcode project for manual signing
   - `flutter build ipa --release` → export → `xcrun altool` → TestFlight
6. Telegram sends `🚀 Build Started` on start, `✅ Build Completed` on success, `❌ Build Failed` on error.
7. Source detection: `💻 username@hostname` (local) or `🤖 GitHub Actions Pipeline` (CI).

## Alternative Flows

- **AF1 — Platform flag**: `ios` / `android` / `all` (default).
- **AF2 — Missing Firebase token**: skips Firebase upload, continues to Play Store.
- **AF3 — Missing Play Store JSON**: skips Play Store upload.
- **AF4 — Build failure**: prints log tail, sends Telegram failure message, exits with error.

## Acceptance Criteria

- [x] `./deploy.sh ios` → IPA uploaded to TestFlight
- [x] `./deploy.sh android` → APK on Firebase + AAB on Play Store (internal)
- [x] `./prod.sh` → internal testing track on both platforms
- [x] Telegram notifications with platform emoji + source
- [x] GitHub Actions auto-deploy on merge to `uat` (Firebase + Play Store internal for Android)
- [x] `scripts/prepare.sh` generates all secrets from `.app_dist/`
- [x] `.env.prod.git_vars.json` ready for `gh secret set -f`

## Notes

- All secrets in `.env.prod` (gitignored) and GitHub Secrets.
- `.env.example` is the safe-to-commit template.
- `resources/git_vars.json` tracks which secrets are configured.
- Version auto-parsed from `pubspec.yaml` — single source of truth.
- Both `deploy.sh` and `prod.sh` upload to Google Play Store **internal testing** track (not production).
