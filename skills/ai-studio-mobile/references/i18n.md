# i18n recipe (runtime language switch, native)

Goal: user picks a language in Settings and the UI changes immediately, including RTL for Arabic.

## iOS — in-code string table (instant switch, no bundle swizzling)
- `enum Lang: String, CaseIterable { case en, vi, ko, ja, ar, zh ... var isRTL }`
- `enum L10n { static var current: Lang (UserDefaults); static func t(_ key) -> String }`
  backed by a `[String: [Lang: String]]` table; global `func L(_ k) -> String`.
- On change: save language, `UIView.appearance().semanticContentAttribute = isRTL ? .forceRightToLeft : .forceLeftToRight`,
  then rebuild the root: `window.rootViewController = AppCoordinator().makeRootViewController()` with a crossfade.
- Apply RTL at launch in `AppDelegate` before building the window.
- Replace ad-hoc `isVI ? ... : ...` ternaries with `L("key")`.

## Android — resource qualifiers + LocaleHelper
- Keep `values/` as the default language; add `values-en`, `values-ko`, `values-ja`, `values-ar`, `values-zh`.
- `LocaleHelper.wrap(Context)`: read saved code; if non-empty build a `Locale`, `Locale.setDefault`,
  `Configuration.setLocale` + `setLayoutDirection`, return `createConfigurationContext(cfg)` (API 17+).
- Override `attachBaseContext(base)` in **every** Activity: `super.attachBaseContext(LocaleHelper.wrap(base))`.
- Language picker (AlertDialog single-choice) → save code → restart task via the launcher intent
  (`FLAG_ACTIVITY_CLEAR_TOP | FLAG_ACTIVITY_NEW_TASK`).
- `android:supportsRtl="true"` in the manifest handles Arabic layout mirroring.

## Coverage
- Localize all visible surfaces: controls (Start/Pause/Reset), settings labels + section headers,
  support screen, duration picker, dialogs/toasts. Untranslated keys fall back to the default language.
